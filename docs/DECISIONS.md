# LeadFlow — Platform Decisions & Research Log

Every platform fact the design depends on, where it was confirmed, and what was decided. Researched 2026-10-04 using official sources only (help.make.com, apps.make.com, make.com, ai.google.dev, netlify.com / docs.netlify.com, developers.google.com, docs.slack.dev (api.slack.com), slack.com/help, plus hbr.org for the cited study). PRD and ARCHITECTURE reference rows as `DECISIONS #n` or `#n`.

**Status key:**
- ✅ Confirmed by docs
- 🟡 Decided (conservative choice: works whether or not the open assumption holds)
- 🧪 Test at build step N: design kept, with a pass/fail check at that step of ARCHITECTURE §10 and the fallback written below

Builder: if a 🧪 check fails, apply the fallback, update this row to ✅ or 🟡 with what you observed, and update the affected spec sections in the same commit.
